# 설계 판단 (초안)

이 문서는 실습을 진행하며 내린 설계 판단을 정리한 초안이다. 각 절 끝의 표시가 붙은 부분은 작성자가 자기 말로 다시 쓸 자리다.

## 1. 왜 Graphiti를 그대로 쓰지 않았나

Graphiti는 대화나 문서에서 LLM으로 엔티티와 관계를 뽑아 시간 정보가 붙은 지식 그래프를 만든다. 관계(엣지)마다 유효 시작·끝과 기록 시각을 두고, 새 사실이 옛 사실과 충돌하면 옛 엣지를 지우지 않고 무효화한다. 이 "유효 기간과 무효화" 아이디어가 이 실습이 풀려는 문제(시점이 다른 값이 섞이는 기록)에 정확히 맞는다.

그대로 쓰지 않은 이유:

- **데이터가 비공개이고 처리를 전부 로컬에서 해야 했다.** Graphiti의 추출·중복 판정·무효화 판단은 LLM 호출에 기대는데, 개인 건강 기록을 외부 API로 보내지 않는다는 조건이 먼저 있었다. 로컬 LLM으로 바꾸면 추출 품질을 따로 검증해야 해서, 실습의 초점(시간 처리가 검색을 얼마나 바꾸나)이 흐려진다.
- **필요한 범위가 그래프보다 훨씬 좁다.** 대상은 한 사람이고, 시점 질문이 실제로 묻는 속성은 몇 개(체중, 체성분, 식단 한도, 운동 구성, 작업 중량)다. 엔티티 해소나 관계 탐색이 필요 없어서, (대상, 속성, 계열)별 체인을 가진 표 한 장이면 유효 기간과 무효화를 그대로 표현할 수 있다.
- **비교 실험이 목적이었다.** A-D를 같은 인덱스와 같은 평가셋에서 한 단계씩 쌓아 무엇이 어느 지표를 바꿨는지 보려면, 각 단계가 작고 결정적(같은 입력 → 같은 출력)이어야 했다. LLM 추출이 들어가면 실행마다 결과가 달라질 수 있다.
- **그 대가:** 사실표를 규칙 후보와 사람 확인으로 만들었고(규칙 적중 117개 중 62개), 속성 밖 질문에는 답하지 못한다(D 응답률 0.43). Graphiti식 자동 추출이 필요해지는 지점이 바로 여기다.

## 2. 왜 사실표에 측정 계열과 성격 칸을 두었나

**측정 계열.** 같은 사람의 체중이라도 아침 공복, 식후, 운동 직후, 특정 기간의 오후 측정은 서로 비교할 수 없는 값이다. 유효 기간 체인을 (대상, 속성) 하나로만 이으면, 식후에 잰 값이 들어오는 순간 아침 공복 값의 유효 기간이 닫히고 "현재 값"이 조건이 다른 값으로 바뀐다. 그래서 체인을 (대상, 속성, 계열) 단위로 잇고, 기본 답은 기본 계열(기상 직후 공복)만 쓰며, 다른 계열은 "참고"로 보인다. 계열을 정할 근거가 기록에 없을 때는 기본값을 무리하게 적용하지 않고 "미확인"으로 두었다. 그 판단은 사람이 확인했다(표본 12건).

**성격 칸.** 기록에는 측정값, 사용자가 정한 목표·한도, 대화 중 나온 제안, 계산한 추정이 같은 모양(숫자+단위)으로 적힌다. 목표 체중이나 전망치가 측정값처럼 잡히면 "그때 체중"이 틀린다. 원래 기록이 이미 "사용자 사실·당시 제안·실제 채택"을 구분하는 규칙을 갖고 있어서, 이를 `성격`(측정 / 사용자 결정 / 사용자 보고 / 제안 / 추정) 칸으로 옮겼다. 제안·추정은 별도 체인이라 측정·결정 값을 닫지 않고 답에서도 참고로만 나온다.

두 칸 모두 "값이 언제부터 언제까지 참이었나"를 정하는 데 필요한 최소 정보라서 두었다. 조건 근거(`조건 근거`)를 따로 남긴 것도 같은 이유다. 나중에 사용자 설명이 바뀌면 어떤 행이 그 설명에 기대고 있는지 찾을 수 있어야 한다.

## 3. 왜 평가셋을 따로 만들었나

검색 규칙(필터, 반감기, 후보 수, 사실표 답 순서)은 조정할 손잡이가 많다. 평가 질문을 보면서 이것들을 고르면 숫자는 좋아지지만, 그 숫자는 이 40문항에 맞춘 결과일 뿐 일반적인 개선인지 알 수 없다.

그래서:

- **평가셋은 구현을 보지 않은 별도 세션이 실제 기록만 읽고 초안을 썼다.** 사람이 말투와 정답을 확인해 확정했다. 질문을 만드는 쪽이 검색기의 약점을 모르게 하려는 것이다.
- **규칙과 파라미터는 공개 데모 볼트(합성 데이터)와 직접 쓴 개발용 질문으로만 정했다.** 정한 뒤 커밋으로 고정하고, 비공개 평가셋은 모드마다 한 번만 돌렸다.
- **결과를 본 뒤 바꾼 것은 "사후"로 표시하고 바꾸기 전 숫자를 남겼다.** 지표 추가, 메타데이터 정리, 사실표 확인 반영이 그 예다.
- **데모 평가셋은 공개 재현용이다.** 다만 D의 규칙 일부를 데모로 정했기 때문에, 데모의 D 숫자는 독립 검증이 아니다.

40문항은 작아서 부트스트랩 구간이 넓다. 이 실습의 숫자는 "어떤 유형에서 어떤 단계가 무엇을 바꿨나"를 보는 데 쓰고, 모드 간 작은 차이를 결론으로 삼지 않는다.
